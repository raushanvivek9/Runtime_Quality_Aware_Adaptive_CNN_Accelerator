Stage 8C End-to-End Runtime Adaptive Accelerator RTL Prototype

1. Objective
Stage 8C demonstrates a real RTL control path from activation-derived runtime
statistics, through a Stage 8A resource decision, to a captured Stage 8B PE
configuration and deterministic GEMM computation.

2. Stage 8A integration
The existing runtime_controller_top is instantiated unchanged. Its runtime
monitor, feature calculator, quality estimator, and resource controller feed
the Stage 8C boundary through decision_valid and resource_cfg.

3. Stage 8B integration
The existing adaptive_compute_top is instantiated unchanged. It retains the
existing adaptive PE controller, 64-PE physical array, and 8x8 GEMM workload.

4. End-to-end architecture
Activation stream -> Runtime Monitor -> Features -> Quality Estimator ->
Resource Controller -> decision_valid/resource_cfg -> Resource Capture ->
Adaptive PE Array -> GEMM Result.

5. Handshake protocol
layer_end creates Stage 8A statistics. The registered Stage 8A decision_valid,
not layer_end, triggers the integration capture. compute_start is issued after
that capture, so Stage 8B cannot begin before a valid decision exists.

6. Resource capture
captured_resource_cfg is registered only for an accepted decision and drives
Stage 8B. The testbench changes a test-only live candidate while each workload
is busy; the integration capture, Stage 8B capture, PE-enable mask, and active
PE count remain stable.

7. Layer workload
conv1 (layer 0): [1, 0, 1, 0]
conv2 (layer 1): [0, 3, 0, -3]
conv3 (layer 2): [0, 4, 0, -4]
These streams are monitoring stimulus. The Stage 8B workload is a separate,
representative deterministic 8x8 integer GEMM, not a full CNN convolution path.

17. Limitations
This is an RTL integration prototype, not a complete CNN accelerator, Eyeriss
implementation, SCALE-Sim RTL implementation, energy model, physical hardware
implementation, or neural-network accuracy evaluation. It makes no claims
about accuracy, energy, power, area, timing, FPGA, ASIC, or physical hardware.
Stage 8C does not alter Stage 1-7 results, including the validated Stage 7
conclusion that 64 PE is the only jointly feasible configuration under the
current performance, energy, and degradation constraints.

18. Stage 9 recommendation
Use this captured-decision boundary as the control interface for a future
layer-data-path integration. Any Stage 9 work should retain explicit numerical,
performance, and energy validation rather than infer those properties from this
functional simulation.
